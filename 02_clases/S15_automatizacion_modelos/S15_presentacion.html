¿Por qué automatizar en proyectos territoriales?

En un estudio de impacto ambiental o plan de cuenca, los datos se actualizan permanentemente. Si el trazado de una vía o el umbral de pendiente cambia, un modelo automatizado recalcula todo en un clic.

1. Cero Errores Manuales

Elimina el riesgo de olvidar un parámetro, usar un CRS incorrecto o equivocarse en el orden de capas.

2. Trazabilidad Contractual

El diagrama del modelo sirve como memoria técnica visual y demostración ante interventorías y autoridades ambientales.

3. Equivalencia Total QGIS / ArcGIS Pro

El concepto de Grafo Acíclico Dirigido (DAG) es idéntico en ModelBuilder (.atbx) y en el Diseñador Gráfico de Modelos de QGIS (.model3). Pueden elegir cualquiera de los dos para su Entrega Final.

Bloque 1 · Lenguaje Visual

Anatomía de ModelBuilder y Equivalencia en QGIS

La gramática visual del geoprocesamiento (ArcGIS Pro & QGIS)

Los tres elementos de un modelo espacial automatizado

Tanto en ModelBuilder como en el Diseñador Gráfico de Modelos de QGIS (Procesos → Diseñador de modelos), los datos fluyen a través de algoritmos conectados.

1. Entradas (Óvalos Azules / Inputs)

Datos y Parámetros Iniciales

Capas vectoriales (drenajes), rásteres del terreno (DEM_12m.tif, NDVI.tif) o valores numéricos (distancia de retiro de 30 m).

2. Algoritmos (Rectángulos Amarillos / Blancos)

Herramientas de Proceso

Geoprocesos que transforman datos: Buffer, Clip, Slope, Calculadora Ráster, Polygonize e Intersect.

3. Salidas (Óvalos Verdes / Outputs)

Productos Derivados

Nuevas capas espaciales generadas por cada eslabón que alimentan automáticamente el siguiente paso hasta producir la capa final.

El código de colores en pantalla

Estados de un modelo en ModelBuilder

Blanco

Incompleto / No Listo

La herramienta aún no tiene todos los parámetros obligatorios configurados. No se puede ejecutar.

Con Color

Listo para Ejecutar

Azul, amarillo y verde brillantes. Todos los parámetros están validados y el modelo está listo para correr.

Con Sombra

Ya Ejecutado con Éxito

El rectángulo amarillo y el óvalo verde muestran una sombra gris proyectada. El dato ya fue creado físicamente en el disco.

Convertir variables en parámetros de usuario (P)

Si dejan las rutas quemadas dentro del modelo, solo servirá para ese archivo exacto. Al marcar una variable como parámetro, se convierte en un campo interactivo.

Clic derecho → Model Parameter

Aparecerá una letra P mayúscula sobre el óvalo azul o verde. Esto indica que la variable se expondrá hacia el usuario final.

Habilidad 1 · Todos al tiempo en su computador

Práctica en vivo: armen el modelo de amenaza

Actividad en vivo (15 minutos)

Construyan el modelo automatizado de zonificación de amenaza para La Iguaná:

  • Abran ModelBuilder y creen el flujo conectando: Buffer de drenajes → Slope del DEM → Intersección de amenaza.

Bloque 4 · Código y Extensibilidad

Exportación a Scripts de Python (ArcPy / PyQGIS)

El puente entre lo gráfico y la programación

Exportar el modelo visual a código Python

Cada cajita de ModelBuilder es en realidad una línea de código en Python utilizando la librería ArcPy (o processing.run en PyQGIS).

Exportación en 1 Clic

Menú superior de ModelBuilder: Model → Export → Export to Python File… (guarda un archivo .py ejecutable).

Ventajas del Script

Se puede programar en el programador de tareas del servidor para ejecutarse automáticamente todas las noches o integrarse a tableros web interactivos.

Anatomía del script generado

Cómo se ve el código Python generado

import arcpy

# Definir entorno de trabajo y sobrescritura
arcpy.env.workspace = "C:/SIG/Iguana_Corporativa.gdb"
arcpy.env.overwriteOutput = True

# 1. Buffer de retiros hídricos a 30 metros
retiros = arcpy.analysis.Buffer("drenajes_iguana", "retiros_30m", "30 Meters")

# 2. Pendiente en grados a partir del DEM reproyectado
pendiente = arcpy.sa.Slope("DEM_Iguana_CTM12_12m", "DEGREE", 1.0)
pendiente.save("pendiente_grados")

# 3. Intersección final de áreas expuestas
arcpy.analysis.Intersect(["retiros_30m", "laderas_criticas"], "amenaza_alta_final")
print("¡Modelo ejecutado exitosamente con ArcPy!")

Bloque 5 · Cartografía Editorial

Diseño de Layouts y Salidas en ArcGIS Pro

De la pantalla al plano de ingeniería

Estructura de un Layout en ArcGIS Pro

A diferencia de la vista de trabajo dinámica (Map), el Layout representa la hoja física de impresión con escala congelada y elementos normativos.

1. Insert Layout

Formato de Hoja

Pestaña Insert → New Layout. Seleccionar tamaño normativo ANSI D / ISO A3 horizontal (420 × 297 mm) para proyectos de ingeniería.

2. Map Frame

Marco de Mapa Activo

Insertar Map Frame vinculando el mapa 2D del proyecto. Definir escala redonda fija (ej. 1:25 000) y activar navegación para centrar La Iguaná.

3. Grilla CTM12

Sistema de Referencia

Añadir Grid → Measured Grid forzada a MAGNA CTM12 (EPSG:9377) con intervalos métricos regulares (cada 1 000 m o 2 000 m).

Rigor cartográfico profesional

Elementos Dinámicos de Salida

Elementos Obligatorios
  • Norte Geográfico: Flecha de norte vinculada al Map Frame (rota automáticamente si el mapa rota).
  • Escala Gráfica Dinámica: Barra métrica calibrada en metros o kilómetros que se actualiza si cambia el zoom.
  • Leyenda Inteligente: Filtrada para mostrar únicamente las capas visibles en el encuadre actual.
  • Membrete Técnico: Título oficial, sistema de coordenadas EPSG:9377, autor, fecha y fuente de datos (AMVA / IGAC).
Exportación Editorial

Formatos de Entrega

Pestaña Share → Export Layout:

  • PDF Vectorial (300 DPI): Tipografías incrustadas, capas vectoriales conservadas para revisión de interventoría.
  • TIFF Georreferenciado: Para integrar mapas diseñados como fondos ráster en otros sistemas.
